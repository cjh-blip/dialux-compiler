# 家具识别与 DIALux 放置设计

状态：已确认设计
日期：2026-09-08
范围：家具识别、家具 IR、首个 DIALux 家具执行切片

## 1. 目标

把图纸中的家具从“解析器识别出的几何数据”推进为可审查、可验证、可进入 DIALux 的软件能力。

首个基线是样例图纸（DWG/DXF）：解析结果必须保持 1 个房间和 26 件家具。第一
个执行切片只要求 1 件家具完成真机闭环，再扩展到 26 件。

家具的直接业务目的，是为后续桌面照度评估提供准确的位置、尺寸和高度；三维视觉还原不是本
切片的独立目标。

## 2. 非目标

- 本切片不同时实现 PDF 家具识别；PDF 分为矢量 PDF、扫描 PDF 和文字标注 PDF，另立输入适配任务。
- 不把视觉模型作为主识别器。
- 不在家具切片中同时实现桌面计算面。
- 不以家具伪 space 导入 STF；该路线已被真机判定为错误。
- 不一开始接入真实 `.m3d` 家具库；先验证 Cuboid 原语。

## 3. 总体架构

```text
DWG/DXF
  -> 几何候选抽取
  -> 房间/家具分类与去重
  -> 房间归属与置信度
  -> 家具 IR
  -> 预览/校验
  -> FurnitureTask
  -> DIALux FurnitureTool
```

识别层与执行层分离。同一份家具 IR 必须既能用于 SVG/JSON 预览，也能供 DIALux 执行器使用。

## 4. 家具识别设计

### 4.1 主识别策略

识别采用确定性、多信号流水线：

1. 读取闭合几何环并统一单位为米。
2. 以面积阈值生成候选，面积阈值只能是候选条件，不能作为唯一语义判断。
3. 使用闭合关系、房间环、图层、块/实体来源和几何形状增强分类。
4. 对重复环、包含关系和同一对象的多重表示去重。
5. 将候选归属到包含它的房间；无法确定时保留候选并降低置信度。
6. 输出来源信息，保证每件家具可追溯到图纸实体。

现有样例图纸的 `1 房间 + 26 家具` 结果是回归基线，不允许因增强规则而改变。

### 4.2 家具 IR

每件家具输出以下字段：

```json
{
  "id": "LINEARC_001_<hash>",
  "room_id": "WALLRING_000_<hash>",
  "polygon": [[x1, y1], [x2, y2], [x3, y3], [x4, y4]],
  "bbox": [x_min, y_min, x_max, y_max],
  "area_m2": 0.45,
  "kind": "unknown",
  "height_m": 0.75,
  "rotation": 0.0,
  "confidence": 1.0,
  "source_layer": "",
  "source_entity": ""
}
```

字段约定：

- `polygon`、`bbox`、`area_m2` 使用米制。
- `room_id` 显式记录归属，不再依赖伪 space 名称推断。
- `kind` 先允许 `unknown`，不强行从几何猜桌子类型。
- 会议桌默认 `height_m=0.75`；接口保留逐件覆盖能力。
- `confidence` 用于人工确认，低置信度不得静默丢弃。
- `source_layer`、`source_entity` 用于定位原始 DWG/DXF 证据。

IR schema 兼容策略：在不破坏现有 `space.furniture` 的前提下增加显式字段；家具伪 space 只作为
预览兼容层逐步淘汰，执行层不得把它们当房间。

## 5. DIALux 执行设计

### 5.1 任务边界

新增独立 `FurnitureTask`，工作台顺序为：

```text
RoomTask -> FurnitureTask -> LuminairesTask -> CalculationTask
```

`FurnitureTask` 接收已经生成并校验的 IR，不重新解析 DWG。首个版本只处理一个家具对象，之后
扩展到批量 22 件。

### 5.2 原语路线

第一切片使用 Cuboid：

- 进入 `MenuGotoShowFurnitureTool`。
- 选择目标房间/工作区。
- 创建一个 Cuboid。
- 通过 `CuboidWidth`、`CuboidLength`、`CuboidHeight` 写入尺寸。
- 写入或校准位置与高度。
- 用 IR id 作为 ASCII 对象名，避免中文名称乱码。

多边形拉伸 `aid_DrawExtrusionFurniture` 是第二阶段的精确几何路线。真实 `.m3d` 原型库不是首
个切片依赖。

### 5.3 坐标策略与退出条件

优先寻找选中家具后的可写 X/Y/Z 属性。若 UIA 没有数值位置控件，采用经校准的 CAD 视口坐标
映射；映射层必须独立于家具业务逻辑，并记录屏幕坐标到米制坐标的变换。

若已经证明无数值坐标入口，且校准点击连续三次无法达到验收误差，则停止继续堆 UIA，转入 `.evo`
STEP 结构实验。任何 `.evo` 修改只操作副本，必须重开 DIALux 并同时做三维与 STEP 验证。

## 6. 错误处理

- 首个切片采用失败即停，错误必须包含家具 id、阶段和可行动建议。
- 底层动作允许有限重试；禁止无限重试。
- 低置信度识别结果进入人工确认，不静默丢弃。
- 找不到房间归属、单位异常、polygon 自交或尺寸非正时，在执行前失败。
- 已生成的半成品不回滚时，界面必须明确显示停止步骤和半成品状态。

## 7. 验收标准

### 7.1 识别层

- 样例图纸：1 房间、26 家具，现有真实解析测试保持通过。
- 每件家具都有 polygon、bbox、面积、room_id、来源信息和置信度。
- 增加小房间、柱子、墙垛、重复环、开放线等反例，验证误判和漏判不会静默发生。
- 预览图能显示家具位置，且与 IR 同源。

### 7.2 DIALux 单件闭环

- 1 件 Cuboid 在正确房间内生成。
- 中心位置和长宽误差不超过 10 mm。
- 高度误差不超过 1 mm。
- DIALux 三维视图位置正确。
- `.evo` 拆包存在正确的 `FurnitureElement`，不是额外建筑或 ROOM。
- 重开工程后家具仍存在。

### 7.3 批量扩展

- 22 件家具逐件可追溯到 IR id。
- 任一失败都停止并报告 id，不得静默少放。
- 批量完成后再进入桌面计算面设计。

## 8. 测试策略

- 先写识别字段、归属、置信度和反例的单元测试。
- 再写 `FurnitureTask` 的离线测试，使用依赖注入替换 UIA 真机调用。
- 真机只作为最后一层验收：单件 Cuboid、`.evo` 拆包、重开工程、三维人工确认。
- 门禁沿用项目标准：`python -m pytest tests/ -q` 与 `python -m ruff check .`。

## 9. 开发顺序

1. 固化家具 IR 字段和识别反例测试。
2. 实现单件家具选择、尺寸/高度输入和对象命名。
3. 探测并实现位置数值通道；没有时接入校准视口映射。
4. 新增 `FurnitureTask`，接入工作台但默认保持显式开关。
5. 完成单件真机闭环并拆包验收。
6. 扩展到 22 件，补齐失败报告和批量回归。
7. 单独设计桌面计算面。

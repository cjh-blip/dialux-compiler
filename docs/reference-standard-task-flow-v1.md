# 标准任务流程（六步链）

> 场景：个人标准工作流 | 用途：从想法到交付的完整链路 | 版本：v1（2026-08-22 定案）
> 来源：项目内部梳理确认（batch-grill-me → 三省（可选）→ plan → karpathy-guidelines → neat-freak）

## 一句话

把一件事从「模糊想法」推进到「干净交付」的六步链：**拷问定案 → 决策（必要时）→ 计划 → 按准则执行 → 洁癖收尾**。

## 六步链

| 步骤 | 动作 | 触发条件 | 产出物 |
|---|---|---|---|
| ① 素材/截图 | 读懂输入（截图、资料、附件），确认要做什么 | 每次拿到外部素材先看清内容 | 内容要点 + 用途确认 |
| ② grill（batch-grill-me） | 批量拷问：把设计树前沿问题一次抛完，每条带推荐答案，用户确认或改 | 有想法/任务需要定案 | 决策表（问题 + 定案） |
| ③ 三省六部制 | 多 Agent 对抗决策 | **仅当遇到实在难以决定的** | 最优方案结论 |
| ④ plan | 把定案落成执行计划文档 | 决策已定 | 计划文档（步骤/文件/风险） |
| ⑤ karpathy-guidelines | 按行为准则执行计划 | 计划在手 | 实际产出 |
| ⑥ neat-freak | 执行完对账收尾：文档/记忆/工作区对齐 | 执行完成 | 无残留、规则与事实对齐 |

## 关键规则

1. **grill 带建议**：grilling 的每个前沿问题都给推荐答案，不是干问
2. **三省可选**：不是每次都走，只在难以决定时叠加（重大决策/需要多视角对抗）
3. **执行遵守 Karpathy 准则**：先想清楚、简洁优先、精准修改（surgical）、目标驱动（goal-driven）
4. **neat-freak 必收尾**：执行完必须对账，删除候选需用户确认，记忆写入需授权
5. **截图是输入层**：截图处理（读懂+确认用途）不属于决策链本身，发生在 grill 之前

## 调用示例

- 用户说「走标准流程」→ 按六步链执行
- 用户丢来截图没配文 → 先走①，读懂后确认用途再决定是否进②
